Twitch scope guide for DevilMedlar and MedlarTV
Checked October 4, 2026

What this file covers

The supplied diagnostic report lists 99 distinct scope names for DevilMedlar
and the same 99 for MedlarTV. The main inventory below contains each name
once: 80 current API/chat permissions, 1 current sign-in permission, and
18 historical permissions still present in the reported grants. Both accounts
have every main-inventory entry in that report. No scopes were added to or
removed from either account while making this guide.

The old scopes file had 74 entries. It missed 27 names from the reported
grants and included 2 names that were not in either reported grant. Those
2 old names are preserved in a separate appendix, outside the 99-entry
inventory. This is a readable permission guide, not a paste-ready list of
permissions an app should request.

A scope is a permission slip

Imagine the app is a helper and Twitch has many locked doors. A scope is a
permission slip for one kind of door. A token is the credential the helper
shows Twitch. Having the slip does not mean the helper has used the door,
that the code works, or that every action is available to the account.

READ means look. CHANGE means change something. SEND means publish a message.
READ EVENTS means Twitch tells the app when something happens; it does not
necessarily mean the app can look back through all old events. An API is a
set of actions a program can ask Twitch to do. An endpoint is one specific
action. EventSub is Twitch's current system for sending event notifications.

The broadcaster owns the channel. A moderator is a helper with channel chat
powers. An editor is a different channel helper role. A bot is an automated
account. Granting a scope does not give the account any of these roles.

'Your' or 'authorizing user' means the account that gave the permission.
A scope on MedlarTV's token does not automatically control DevilMedlar's
channel. Channel-owner actions generally need DevilMedlar's authorization;
moderator actions need the appropriate role and matching account/channel
identities. Each action also checks the token type, app identity, available
feature, and any additional scopes or limits. An app token identifies the
app; a user token identifies an authorizing account. Neither is printed here.

Grant present is not function tested. The diagnostic grant lists prove only
what permissions Twitch reported for those tokens at that time. This guide
checks the documented meaning, not successful execution of all 99 features.
Historical names are kept for full coverage; they are not working aliases
for similarly named modern scopes. Use only the permissions a feature needs.

How to read the entries

Each entry gives the exact scope name, what it permits, a simple example,
and a boundary or extra requirement. Sources [1]-[9] are linked at the end.
For current scopes, [1] and [2] are the official catalog and action reference;
[3] covers notification-specific requirements. Role checks in these sources
still apply even when an example sounds simple.

MAIN INVENTORY

A. Current API and chat permissions

001. analytics:read:extensions
  Type: READ
  What it does: See reports about Twitch extensions you develop. An extension is a small
  extra panel or tool added to a stream.
  Example: download a report showing how people used your extension.
  Limits: This is developer analytics, not permission to read every viewer's private
  information. The app/user must have the required ownership or access to the extension.
  Sources: [1], [2], [3].

002. analytics:read:games
  Type: READ
  What it does: See Twitch viewing reports for games your developer organization owns.
  Example: download a report about people watching streams of your game.
  Limits: This does not give reports for every game or let you change a game. The
  developer organization must have access to it.
  Sources: [1], [2], [3].

003. bits:read
  Type: READ
  What it does: See your channel's Bits information, such as its Bits leaderboard. Bits
  are Twitch's paid cheering items. It also authorizes supported cheer, Bits-use, and
  custom Power-up redemption notifications; Power-ups are special channel interactions
  bought with Bits.
  Example: show which viewers have cheered the most Bits.
  Limits: This does not buy, spend, refund, or transfer Bits. The broadcaster's account
  must authorize access.
  Sources: [1], [2], [3].

004. channel:bot
  Type: BOT AUTHORIZATION
  What it does: Let an app's bot use supported chat actions in the broadcaster's channel
  with the app's own access token.
  Example: the broadcaster allows a cloud bot to receive chat or send
  messages in this channel.
  Limits: It is one piece of permission, not a general master key. The bot user's
  user:bot and the particular read/write chat scope are also needed where specified;
  moderator status can be an alternative to channel:bot for documented flows.
  Sources: [1], [2], [3].

005. channel:edit:commercial
  Type: CHANGE
  What it does: Start a commercial break on the authorizing broadcaster's channel.
  Example: request a 60-second ad break during a live stream.
  Limits: The channel must be eligible and live, and Twitch controls accepted lengths,
  timing, and cooldowns. This does not grant ad-schedule control or guarantee every
  viewer sees an ad.
  Sources: [1], [2], [3].

006. channel:manage:ads
  Type: CHANGE
  What it does: Snooze the broadcaster's next scheduled automatic ad by five minutes
  when a snooze is available. The reply includes next-ad and remaining-snooze
  information.
  Example: postpone an ad so it does not interrupt an important moment.
  Limits: The name does not mean unrestricted control over every ad setting. Snoozes are
  limited, the channel must be eligible, and starting a commercial uses
  channel:edit:commercial. Reading the schedule through Get Ad Schedule separately
  requires channel:read:ads.
  Sources: [1], [2], [3].

007. channel:manage:broadcast
  Type: CHANGE AND READ
  What it does: Change supported channel information, including the stream title,
  game/category, language, and tags, and create/read stream markers.
  Example: change the title to 'Learning a new game' or save a marker at an
  exciting moment.
  Limits: This changes Twitch channel information, not the local camera, microphone,
  game, or streaming program. Individual fields and actions have their own restrictions.
  Sources: [1], [2], [3].

008. channel:manage:clips
  Type: CHANGE AND READ
  What it does: As a broadcaster, create clips from your saved broadcasts and get
  download links for your channel's clips.
  Example: make a clip from yesterday's recorded stream, then request its
  download link.
  Limits: A saved broadcast is often called a VOD. This is limited to the broadcaster's
  channel and the documented clip actions, not arbitrary editing of anyone's clips.
  Sources: [1], [2], [3].

009. channel:manage:extensions
  Type: CHANGE
  What it does: Manage extension activation/configuration on the authorizing
  broadcaster's channel.
  Example: put an installed interactive extension into an available channel
  slot.
  Limits: The official scope catalog describes extension configuration. However, the
  current Update User Extensions action explicitly requires user:edit:broadcast. Do not
  assume this grant alone passes that action. It does not control other channel settings
  or install software on a computer.
  Sources: [1], [2], [3].

010. channel:manage:guest_star
  Type: CHANGE AND READ
  What it does: As the broadcaster, manage the supported Guest Star session, settings,
  invitations, guest slots, and slot settings.
  Example: invite a guest and assign that guest to a stream slot.
  Limits: These actions can affect who appears in the guest session. Twitch's feature
  access and individual action requirements still apply; this is not control of guests'
  computers. Twitch marks these Guest Star API actions as beta, meaning they may change.
  Sources: [1], [2], [3].

011. channel:manage:moderators
  Type: CHANGE AND READ
  What it does: Add or remove moderators on the authorizing broadcaster's channel. It
  also permits reading the moderator list.
  Example: give a trusted helper the moderator role.
  Limits: This changes another person's channel powers. Only the broadcaster's
  authorization is enough for these channel-owner actions; being a moderator does not
  let a bot promote itself.
  Sources: [1], [2], [3].

012. channel:manage:polls
  Type: CHANGE AND READ
  What it does: Create, read, and end polls for the authorizing broadcaster's channel.
  Example: ask viewers which game to play and end the poll after voting.
  Limits: This does not cast votes for viewers. Twitch's eligibility, choice, duration,
  and active-poll limits still apply.
  Sources: [1], [2], [3].

013. channel:manage:predictions
  Type: CHANGE AND READ
  What it does: Create/read Channel Points Predictions and lock, resolve, or cancel them
  on the broadcaster's channel.
  Example: stop new predictions when a match starts, then choose the
  winning outcome afterward.
  Limits: Choosing an outcome affects viewers' Channel Points. Twitch's eligibility and
  timing rules still apply; this is not permission to spend real money.
  Sources: [1], [2], [3].

014. channel:manage:raids
  Type: CHANGE
  What it does: Start or cancel an outgoing raid from the authorizing broadcaster's
  channel. A raid sends the audience toward another live channel.
  Example: send viewers to a friend's stream after your stream ends.
  Limits: It does not control the destination channel. Twitch's raid availability and
  timing restrictions still apply.
  Sources: [1], [2], [3].

015. channel:manage:redemptions
  Type: CHANGE AND READ
  What it does: Create, change, and delete custom Channel Points rewards, and manage
  their redemption requests.
  Example: create a 500-point reward or mark a viewer's request fulfilled
  or canceled.
  Limits: The broadcaster authorizes it. An app can only change/delete rewards and
  update redemptions it is entitled to manage, including Twitch's app-created reward
  restrictions; it is not free control of every reward made by other apps.
  Sources: [1], [2], [3].

016. channel:manage:schedule
  Type: CHANGE
  What it does: Create, change, or delete supported stream-schedule entries and update
  vacation settings for the broadcaster's channel.
  Example: move a planned Friday stream to Saturday.
  Limits: This changes Twitch's schedule, not a calendar app or the actual start of a
  stream. One-off/recurring schedule options depend on channel eligibility.
  Sources: [1], [2], [3].

017. channel:manage:videos
  Type: DELETE
  What it does: Delete supported videos belonging to the authorizing broadcaster.
  Example: remove an unwanted saved broadcast from the channel.
  Limits: Deletion can be destructive. The broad name does not grant arbitrary video
  editing, uploading, or deletion on other channels.
  Sources: [1], [2], [3].

018. channel:manage:vips
  Type: CHANGE AND READ
  What it does: Add/remove VIPs and read the VIP list for the broadcaster's channel.
  Example: give a longtime viewer the VIP role.
  Limits: This changes channel roles. The broadcaster must authorize it, and Twitch's

  Sources: [1], [2], [3].

  Type: READ EVENTS

  Example: update a moderation log when a ban happens.

  Sources: [1], [2], [3].

  Type: READ

  Limits: A suspicious label is a warning, not proof of wrongdoing. This does not change
  a user's suspicious status or ban the user.
  Sources: [1], [2], [3].

062. moderator:read:unban_requests
  Type: READ
  What it does: Read appeals from people asking to be unbanned from a channel you are
  allowed to moderate.
  Example: show the moderation team why a banned viewer is asking to
  return.
  Limits: It cannot approve or deny the appeal. Requests can contain private or
  sensitive explanations.
  Sources: [1], [2], [3].

063. moderator:read:vips
  Type: READ EVENTS
  What it does: Receive the supported details about VIP-role changes in Channel Moderate
  notifications. These are event updates about moderation actions in a channel you are
  allowed to moderate.
  Example: let a moderation log record VIP-role changes when they happen.
  Limits: This does not change roles or punish users. It is not by itself permission to
  call the separate full-list actions such as Get Banned Users, Get Moderators, or Get
  VIPs. The notification type can require a combination of additional scopes.
  Sources: [1], [2], [3].

064. moderator:read:warnings
  Type: READ EVENTS
  What it does: Receive supported notifications when a chat warning is sent or
  acknowledged in a channel you are allowed to moderate.
  Example: show that a viewer acknowledged a warning about a chat rule.
  Limits: It does not send warnings and is not a complete historical log unless the app
  separately stores permitted events.
  Sources: [1], [2], [3].

065. user:bot
  Type: BOT AUTHORIZATION
  What it does: Let an app act as this bot user in supported chat actions using the
  app's own access token.
  Example: the MedlarTV account permits the app to use MedlarTV as its chat
  identity.
  Limits: This does not make the bot a moderator or grant every action. The relevant
  chat scope and channel-side authorization are still required for the chosen action.
  Sources: [1], [2], [3].

066. user:edit
  Type: CHANGE
  What it does: Change the authorizing user's profile description, also called their
  bio.
  Example: change a profile bio to say when the user streams.
  Limits: This is not control over the whole account. It does not change a password or
  grant arbitrary account settings access.
  Sources: [1], [2], [3].

067. user:edit:broadcast
  Type: CHANGE
  What it does: Read the authorizing user's installed extensions (including inactive
  ones), and change which supported extensions are active. Extensions are extra tools or
  panels on the channel.
  Example: activate an installed extension in a supported channel slot.
  Limits: Do not treat this as permission for every stream setting. It does not
  automatically grant all of user:read:broadcast; stream title/category changes use
  channel:manage:broadcast.
  Sources: [1], [2], [3].

068. user:manage:blocked_users
  Type: CHANGE
  What it does: Add or remove accounts from the authorizing user's personal block list.
  Example: block an unwanted account or undo a previous block.
  Limits: It does not ban that account from every channel or change another user's block
  list.
  Sources: [1], [2], [3].

069. user:manage:chat_color
  Type: CHANGE
  What it does: Change the color of the authorizing user's name in chat.
  Example: make the bot's chat name blue.
  Limits: It does not change anyone else's name color. Twitch limits which colors are
  available to the account.
  Sources: [1], [2], [3].

070. user:manage:whispers
  Type: SEND AND READ EVENTS
  What it does: Send private Twitch whispers as the authorizing user and receive
  supported incoming-whisper notifications.
  Example: send a private reply and be notified when someone whispers back.
  Limits: This is not access to the user's entire historical whisper inbox or a sent-
  message archive. Whisper eligibility, verification, privacy settings, and rate limits
  still apply.
  Sources: [1], [2], [3].

071. user:read:blocked_users
  Type: READ
  What it does: Read the list of accounts the authorizing user has personally blocked.
  Example: display that user's block list in an account tool.
  Limits: A personal block is different from banning someone from a channel. This does
  not change either list.
  Sources: [1], [2], [3].

072. user:read:broadcast
  Type: READ
  What it does: See the authorizing user's active extensions and read their stream
  markers. A marker is a saved note at a moment in a stream.
  Example: find a marker saying 'great play' when editing a recording.
  Limits: This does not create markers or change extensions. The account and requested
  stream must meet the particular action's ownership/editor rules.
  Sources: [1], [2], [3].

073. user:read:chat
  Type: READ EVENTS
  What it does: Receive live channel-chat messages and related supported chat
  notifications using EventSub, Twitch's system for sending apps event updates.
  Example: a bot receives a message when someone types '!help'.
  Limits: It does not send chat or fetch old chat history. App-token chat flows need the
  additional bot/channel grants or role alternatives documented by Twitch.
  Sources: [1], [2], [3].

074. user:read:email
  Type: READ PRIVATE DATA
  What it does: Read the email address of the user who gave permission.
  Example: an app can learn the email attached to that user's Twitch
  account.
  Limits: It cannot read their email inbox, change the email address, or get other
  viewers' email addresses.
  Sources: [1], [2], [3].

075. user:read:emotes
  Type: READ
  What it does: Read the Twitch emotes available for the authorizing user to use. Emotes
  are small chat pictures.
  Example: let a bot choose an emote that its account can actually send.
  Limits: It does not unlock paid emotes, buy subscriptions, or upload/change channel
  emotes.
  Sources: [1], [2], [3].

076. user:read:follows
  Type: READ
  What it does: Read the channels the authorizing user follows and see which followed
  channels are live.
  Example: show a list of followed streamers who are streaming now.
  Limits: It does not follow or unfollow channels. It does not grant private follow
  lists for arbitrary other accounts.
  Sources: [1], [2], [3].

077. user:read:moderated_channels
  Type: READ
  What it does: Read the channels where the authorizing user has the moderator role.
  Example: list the channels that the bot is allowed to help moderate.
  Limits: It does not give moderation powers in a new channel or list every channel's
  moderators.
  Sources: [1], [2], [3].

078. user:read:subscriptions
  Type: READ
  What it does: Check whether the authorizing user subscribes to a specified channel and
  read the supported subscription details.
  Example: check whether the bot's owner subscribes to a particular
  streamer.
  Limits: This is the viewer's side of a subscription, not a broadcaster's complete
  subscriber list. It cannot buy, renew, or cancel a subscription.
  Sources: [1], [2], [3].

079. user:read:whispers
  Type: READ EVENTS
  What it does: Receive notifications containing new incoming whispers to the user who
  gave permission.
  Example: let an app notice a new private Twitch message.
  Limits: It does not send whispers or fetch the user's entire past whisper history.
  These messages are private.
  Sources: [1], [2], [3].

080. user:write:chat
  Type: SEND
  What it does: Send live chat messages as the authorizing user using Twitch's Send Chat
  Message API, the modern program interface.
  Example: the bot replies to a question in chat.
  Limits: It cannot edit/delete other users' messages. App-token use additionally needs
  user:bot and channel authorization or the documented moderator alternative; chat
  restrictions and rate limits remain.
  Sources: [1], [2], [3].

B. Current sign-in permission

081. openid
  Type: SIGN IN
  What it does: Ask Twitch for an OpenID Connect identity token so an app can recognize
  who signed in.
  Example: an app confirms that a Twitch sign-in belongs to the expected

  Limits: OpenID Connect is a sign-in standard. This does not by itself allow chat,

Important corrections to the original descriptions

- A scope name ending in manage/edit is not a promise of every imaginable
  action on that object. The individual action documentation is decisive.
- clips:edit creates live clips; it does not edit arbitrary existing clips.
- user:edit changes supported profile description data, not the whole account.
- channel:moderate maps to current ban/unban event notifications, not blanket
  permission to execute all modern moderation actions.
- Whisper event permissions do not reveal a complete historical inbox or
  sent-message archive.
- user:edit:broadcast is not a universal superset of user:read:broadcast.
- Reading moderator-role/VIP/ban event categories is not automatically the
  same permission as querying a full list through a different action.
- Ad management here includes limited snoozing, not arbitrary ad scheduling.
- Old scope spellings are preserved without claiming they are modern aliases.
